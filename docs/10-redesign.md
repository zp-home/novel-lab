# 10 · 这一轮改了什么，以及为什么要这么改

> 起因：用户读完前几章，提了三条——①字数偏多，压到 3000~4000；②修饰过重、描述过重；③读起来费劲。
>
> 这三条都不是"再写仔细一点"能修的。它们是生成契约的产物。下面把每一条拆成可测的数字，再讲改法。

---

## 一、先证明「读起来费劲」不是主观感受

拿 `src/ai_flavor.py`（25 个指标，每个都有人类参考值和 AI 参考值）
跑了旧版第 1 章 4122 字，四舍五入如下：

| 指标 | 旧版实测 | 人类参考 | 判读 |
|---|---|---|---|
| 具象词密度 | **95.0 /千字** | 26 | 3.6 倍。每个名词都在被特写 |
| 抽象词密度 | **0.0 /千字** | 4.0 | 一个都没有。全篇没有一句概括或判断 |
| bigram 类型/形符比 | **0.64** | 0.93 | 词汇在自我复制 |
| 4-gram 重复率 | **0.054** | 0.004（AI 线 0.06） | 逼近 AI 参考线，是人的 13 倍 |
| 平均句长 | **12.9 字** | — | 太短 |
| 8 字以内短句占比 | **44%** | 36% | 比人还碎 |
| 句首多样性 | **0.63** | 0.88 | 满篇"林昭…他…沈鹤年…" |

把它翻译成阅读体验：

- **具象 95 / 抽象 0** = 全篇只有物体的外部特征，没有一句"这件事到底要紧在哪"。
  读者得自己从一堆器物里把故事拼出来。这就是"费劲"。
- **4-gram 重复 0.054** = 同一批动作短语在两三千字里反复出现
  （灯笼晃、跺脚、别过脸、嘴张了张、笼进袖子）。读到第三遍就出戏。
- **TTR 0.64** = 词汇高度集中，读起来像在原地打转。

### 根因：不是模型不行，是 prompt 命令它这么写

旧版 `write.py` 里的文体约束是这么写的：

```
- 只写摄像机拍得到的：动作、器物、声音、气味、温度、光影。
- 不写「他感到」「他心想」「他意识到」。
- 每 200 字至少 2 个 8 字以内的短句。
- 段尾停在具体动作或物件上，禁止总结、禁止升华、禁止抒情。
```

这四条合起来，等于一份**禁令清单**：不许写判断，不许写心理，只能写器物，
只能写短句，只能停在物件上。

模型执行得很彻底。它没有变差，它是照做了。

这就是这一轮最重要的一条结论：

> **文体约束必须同时给"要什么"和"不要什么"，而且必须可量化验收。
> 只给禁令，模型会走到禁令的反面极端。**

## 二、改法：把文体做成可插拔的契约

新增 `src/style_contract.py`。一个「文体档案」= 两半：

1. `contract`：一段自然语言写作契约，原样进 prompt。
2. `targets`：一组量化区间，写完之后用 `lint()` 对表，不合格项
   翻译成中文反馈喂回去重写。

目前两个档案：`webnovel`（默认，网文·信息推进）、`literary`（冷硬克制，上一版路线留档）。

`webnovel` 的核心六条：

| 主张 | 为什么 |
|---|---|
| 每个细节必须背功能（每 300 字最多 2 处环境/器物） | 直接压具象词密度 |
| 每 400 字至少 1 处"叙述者的判断" | 补抽象词密度，给读者指路 |
| 平均句长 15~22，短句占 15%~28%，每 300 字要有一个 30 字长句 | 治碎句轰炸和节拍器 |
| 对话占 20%~35%，每轮必须带新信息，禁止空转 | 治"你说呢/嗯"来回 |
| 同一动作描写全章不超过 2 次 | 治 4-gram 复读 |
| 人物介绍只给一次，禁止用"少年/少女/老人/汉子"代称 | 治设定复述和代称滥用 |

### 指标口径也修了三处

| 原来的指标 | 问题 | 改成 |
|---|---|---|
| `abstract`（数 命运/灵魂/意义 这类大词） | 小说里的判断根本不靠这些词，实测恒为 0，白卡 | `judgment`：数 因为/要是/否则/只能 这类因果条件标记 |
| — | 代称是最伤可读性的机器味之一，没有指标 | 新增 `epithet`：少年/少女/老人/汉子/姑娘/兄长… 每千字数 |
| `long25` 只有下限 | 长句过多一样喘不上气 | 加上限 0.28 |

## 三、第二个根因：大纲层的病句在往正文里泄漏

这是排查过程中发现的、比文体更隐蔽的一个 bug。

确定性大纲用模板生成 beat，模板里有这么一条：

```
"{obj}被{doer}{mod}{act}，在{place}。"
```

它生成的中文是：

> 烧焦的账本被林小满**反倒交出**，在雪地里。

「被……反倒交出」不合语法，「在雪地里」悬空。而 prompt 里写着
「本段要落在这个 beat 上」「结尾停在这句上」——模型非常听话，
把病句原样抄进了正文。

同一章里还有：

> 沈鹤年在灯下当着所有人的面按住母亲的铜镜，沉重的力道压得木面发出一声闷响，他手没抖。

（模板 `"{doer}在{place}{mod}{act}{obj}，手没抖。"` + 填充，被扩写后塞进正文）

### 改法：大纲只产出「要点」，不产出句子

`Beat` 增加 `spec` 字段，`Chapter` 增加 `end_spec`。渲染出来长这样：

```
[冲突] 沈鹤年·当着所有人的面按住·母亲的铜镜·灯下｜旁人：没人抬头
[揭示] 林昭·没撕开·过期的药·雪地里｜旁人：谁都没动
[代价] 林小满·反倒交出·烧焦的账本·雪地里｜旁人：谁也没问
[转折] 林昭·又留住·一把锈刀·渡口｜旁人：谁都没拦
```

刻意用 `·` `｜` 分隔、不写成句子，就是为了**让模型没法照抄**。

同时 beat 多了一维「旁人反应」（10 种）。动作本身是信息，旁人的反应才是压力。
组合空间从 13824 涨到 34560/类型，唯一性校验也更容易过。

保留原来的 `text` 字段只做唯一性校验和人工审读，**永不进 prompt**。

## 四、流程也重做了：项目制 + 单一入口

| 之前 | 现在 |
|---|---|
| 参数散在各 CLI，规模/标题/模型写死在代码里 | `projects/<name>.toml` 一份配置 |
| 所有输出进 `out/books/`，两个项目互相覆盖 | `out/<name>/chapters/` 一项目一目录 |
| 进度只在 stdout，Web 没法接 | `out/<name>/manifest.json`，每章刷新 |
| 入口是 `write.py`，编排和生成混在一起 | `src/runner.py` 编排，`write.py` 只写一章 |
| 中断后靠扫目录 | 扫目录 + `index.jsonl` 单章记录（字数/评分/重试次数） |

新目录结构：

```
projects/sijie.toml
src/project.py        项目配置（TOML，含校验）
src/runner.py         流水线入口：世界→人物→大纲→正文→manifest
src/style_contract.py 文体契约 + 量化验收
src/write.py          只负责「写一章」
src/bench_model.py    同题对比多个模型
src/sweep.py          扫 reasoning_effort / 模型的速度×质量拐点
out/<name>/chapters/  正文
out/<name>/manifest.json
out/<name>/index.jsonl
out/<name>/run.log
```

## 六、诚实的部分：还差什么

1. **故事连贯性只做到"卷级"。** 确定性大纲能保证结构节奏和唯一性，
   但保证不了每一段剧情都讲得通。已经改的是：
   - 一个卷（50 章）只认一条线索、一个目标物（`vol_thread`）
   - 每 10 章换一个"看这件东西的角度"（`OBJ_ASPECT`：本体→背面→上的字→缺的那一角）
   - 物件先归材质类，动词从该类里选（`ACT_BY_CLASS`），
     消灭了「摔碎一封信」「割下账本上的印」这种语义荒谬

   没改的是：**语义空间仍然只有 265 种组合**，5000 章平摊下来每条用 75 次。
   结构对，语义空。真正的修法是让卷纲/弧纲由模型生成
   （100 卷 + 500 弧 ≈ 600 次调用），章纲再从弧纲确定性展开。

2. **速度**。实测（同一段 1700 字）：

   | 模型 | 推理档 | 耗时 | 字数 | 契合度 |
   |---|---|---|---|---|
   | gemini-4-hydrogen | high | 237s | 1484 | 47.0 |
   | gemini-4-hydrogen | **medium** | **70s** | 1226 | 41.3 |
   | gemini-4-hydrogen | low | 35s | 996 | 28.1 |
   | gemini-3.8-flash | low | 28s | 1433 | 27.2 |
   | gemini-3.8-flash | medium | 89s | 1680 | 27.0 |

   结论：**gemini-3.8-flash 不能用**（无论档位，契合度都只有 27，
   它写出来的句子 82% 都超过 25 字，等于没听契约）。
   gemini-4-hydrogen medium 是最佳性价比，已做成"medium 起草 → 不过再升 high"的阶梯。

3. **文体档案只有两个**，且都偏男性向冷硬。甜宠、悬疑、儿童向要另写档案。

4. **`literary` 档案没有回归测试**，只是留档。

## 七、这一轮踩出来的四个 bug（都是量出来的，不是猜的）

### 1. 大纲层的病句在往正文里泄漏
模板 `"{obj}被{doer}{mod}{act}，在{place}。"` 生成
「烧焦的账本被林小满**反倒交出**，在雪地里」。
而 prompt 写着「本段要落在这个 beat 上」「结尾停在这句上」，
模型把病句原样抄进正文。
→ 大纲只产出「要点」（`Beat.spec`），用 `·` `｜` 分隔，故意不写成句子。

### 2. 重试没有换来任何改善，只换来了时间
第一版把 15 项文体指标全当硬伤，模型每段都卡在
`sent_cv 0.714 / start_div 0.692` 这种"差 0.01"的边界上，
每段重试 3 次、每章 9 次，一章从 3.5 分钟涨到 6.7 分钟，
最后用的还是降级稿。
→ 拆成「硬伤（触发重写）」和「偏好（只进反馈）」，
并且**文体分改在整章层面算**——1200 字的样本上这些指标抽样噪声太大。

### 3. 截断线比上限还松，导致"写超"永远判失败
`trim_to_length(txt, target*1.35)` 截到 1620 字，但上限 `hi` 是 1380，
截完仍然超，于是判失败重试。
→ 截断线直接等于 `hi`。

### 4. 429 限流时，空稿被当成「✅ 成功」写进正文
gemini 配额打满后，三次尝试全失败，`got` 落成空字符串，
`write_chapter` 照样返回、runner 照样写盘、照样打 ✅。
日志里出现 15 章「✅ 0字 评分77.7 重试9」，
`--force` 模式下等于把已经写好的章一起毁了。
→ 三处修复：429/503/502 指数退避（8/16/32/60 秒）、
`chars < 500` 直接抛错不写盘、manifest 改成**以磁盘为准**
（之前 `set(index) | on_disk` 会把已删的章继续算进"已写"，
Web 控制台上看到的进度是假的）。
