# 四层大纲：一次建完（第 2~5 步）

> 不一步一步来了。总纲 → 卷纲 → 弧纲 → 章纲，一次生成完，直接到正文前一步。

---

## 0. 核心决策：大纲必须确定性生成，不能靠模型

5000 章如果每章调一次模型：

```
5000 次调用 × 1500 tokens ≈ 750 万 tokens，且互相不一致
```

更致命的是**一致性**：模型不知道第 3000 章要呼应第 100 章，因为它没有那个记忆。

所以正确分工是：

```
确定性代码：生成 5000 章骨架（免费、瞬间、绝对一致）
模型：      只在真正写那一章时，把骨架扩成 4000 字正文
```

**模型不参与规划，只参与执行。** 这是 2000 万字可行的前提。

---

## 1. 四层结构

```
全书总纲   1 个    6 幕 + 里程碑
  └ 卷纲  100 个   每卷 50 章
      └ 弧纲  500 个   每弧 10 章
          └ 章纲  5000 个   每章 4 beat
```

| 层 | 数量 | 生成方式 | 内容 |
|---|---|---|---|
| 总纲 | 1 | 硬编码 | 6 幕，每幕的冲突/不可逆/升级 |
| 卷纲 | 100 | 从幕派生 | 卷目标 + "比上卷强在哪" |
| 弧纲 | 500 | 从卷派生 | 起/承/转/合/余 五段 |
| 章纲 | 5000 | 从弧派生 | 4 个 beat + 结尾句 + 转折 |

---

## 2. 六幕：每幕的升级必须"换维度"

这是长篇不烂尾的关键。**不能只是"敌人更强"，要换维度**：

| 幕 | 章号 | 冲突 | 不可逆 | 升级维度 |
|---|---|---|---|---|
| 一·铁匠之子 | 1~400 | 活下去 | 踏入修行，回不去做凡人 | 没有力量 → 有力量但保护不了人 |
| 二·人界之巅 | 401~1600 | 打得过所有人，打不过时间 | 亲手送走妹妹 | **打不过 → 打不得** |
| 三·灵界蝼蚁 | 1601~3000 | 战力还在，但被压成最底层 | 苏见月身死 | **守护 → 复仇** |
| 四·仙界无位 | 3001~4200 | 仙位要夺，夺来的带着因果 | 白蘅消散 | **复仇 → 背负** |
| 五·神界叛徒 | 4201~4600 | 师父是叛神，一直在等他来杀 | 亲手杀了沈鹤年 | **背负 → 背叛** |
| 六·神主 | 4601~5000 | 神格唯一，前任是法则本身 | 成为神主，然后废掉神格 | **成为法则 → 废掉法则** |

**每一幕的"升级"都不是数值，是立场/动机/身份的质变。** 这是 5000 章不重复的根本。

## 3. 确定性生成的三次失败（这部分最值钱）

### 失败 1：组合空间太小

第一版：20×20 标题词库 + 64 个 beat 模板。

```
5000 章只有 20 个唯一标题（每个重复 250 次）
20000 个 beat 只有 138 个唯一值（每个重复 500 次）
```

**校验居然"通过"了**，因为我把阈值设成了 5%。这是最危险的失败模式：**数据烂到没法读，但测试全绿。**

修法：先用生日悖论算出需要多大空间。

```
要 5000 章 90% 唯一  → 空间 ≥ 50000
要 20000 beat 85% 唯一 → 空间 ≥ 120000
```

### 失败 2：哈希低位分布差

把标题扩到 8000 种后，唯一率只有 **0.9%**（比之前还差）。

原因：**FNV-1a 的低位周期极短**，而 `% 20`、`% 12` 恰好只用低位，
所有章号都塌缩到少数几个桶里。

修法：加 splitmix64 风格的 finalizer（雪崩混合）：

```python
h ^= h >> 16
h = (h * 0x7FEB352D) & 0xFFFFFFFF
h ^= h >> 15
h = (h * 0x846CA68B) & 0xFFFFFFFF
h ^= h >> 16
```

效果：0.9% → 74.5%。

**教训：确定性 ≠ 随便写个 hash。分布不好，组合空间再大也没用。**

### 失败 3：模板漏了占位符（最隐蔽）

扩到 160000 空间后，标题 98.4%、beat 68.2%、**结尾句只有 5.8%**。

原因：有些模板只含 `{doer}`，不含 `{obj}` `{place}` `{mod}`：

```python
"{doer}数了数还剩几个人。"     # obj/place/mod 算了却没进文本
```

于是不同章塌缩成同一句：**16 模板 × 3 doer = 48 种输出**，5000 章必然重复 100 次。

修法：**铁律——每个模板必须包含全部占位符。**

效果：结尾句 5.8% → 95.6%。

## 4. 最终数据

```
幕数: 6
卷数: 100
弧数: 500
章数: 5000
beat 总数: 20000
总字数: 20,000,000

[标题] 唯一 4918/5000 = 98.4%
[beat] 唯一 19828/20000 = 99.1%
[结尾] 唯一 4779/5000 = 95.6%
[语义] 唯一 1728 种组合（上限 1728），平均每条用 11.6 次
```

### 诚实的边界：字符串唯一 ≠ 语义不重复

这是最重要的一条。字符串唯一率 99%，但**语义空间只有 1728 种组合**，
20000 条 beat 平均每种用 11.6 次。

也就是说：

> 第 100 章的「林昭把一把锈刀放下，在渡口」
> 和第 4000 章的「沈鹤年把母亲的铜镜推开，在祠堂」

**字符串完全不同，但语义结构一模一样。**

这是确定性生成的**固有局限**。我用一条专门的校验把这件事显式暴露出来，
而不是靠字符串去重糊过去。

**所以：确定性大纲只能保证"结构对"，不能保证"内容好"。**
内容质量必须靠模型在写正文时补。这也是为什么模型只参与执行、不参与规划——
如果连规划都交给模型，成本会涨 10 倍，而结构一致性反而下降。

## 5. 病句检测（确定性生成必踩）

第一版生成了大量病句：

```
在在灯下          ← 重复介词
拆了了            ← 重复助词
把一块碎瓦放下在旧屋  ← 动补搭配错误
```

根因是我把地点存成了 `"在灯下"`，模板里又加了 `"在"`。

我加了一个 `check_grammar()` 检查 13 种病句模式：

```python
_BAD_PATTERNS = [
    ("在在", "重复介词"), ("了了", "重复助词"), ("的的", "重复助词"),
    ("把把", "重复介词"), ("被被", "重复介词"), ("，。", "空逗号"),
    ("。。", "重复句号"), ("放下在", "动补搭配错误"), ...
]
```

第一次跑抓到 **360 处病句**，修完清零。

## 6. 校验（9 项）

| 检查 | 阈值 | 不通过的后果 |
|---|---|---|
| 章号无缝覆盖 1~5000 | 必须 | 流水线卡死 |
| 每章 4 beat + ends_with | 必须 | 正文写不出来 |
| 人物出场正确 | 必须 | 死人复活 |
| 每卷有 escalates | 必须 | 该卷是废的 |
| **章标题唯一率** | **≥90%** | 读者觉得糊弄 |
| **beat 唯一率** | **≥85%** | 同上 |
| **结尾句唯一率** | **≥60%** | 同上 |
| **语义组合覆盖** | ≥80% | 模板多样性不足 |
| **病句** | **0 处** | 直接不能读 |

后 5 项是我踩坑后加的。**第一版的阈值太松，导致数据烂到不能读但测试全绿。**

## 7. 章纲长什么样

```
第2400章《痕灯册八》｜灵帝中期｜4000 字
  目标：在灵帝中期境界下，还清一笔债
    · [冲突] 沈鹤年没摔碎写了一半的信的时候，灯下只有风。
    · [揭示] 林昭没摊开断了的指骨的时候，渡口只有风。
    · [代价] 半张契被玄冥没割下，在旧屋。
    · [转折] 玄冥才把一块碎瓦推回，在雪地里，谁都没拦。
  结尾：苏见月看了一眼一截麻绳，又走了，没回头。
  转折：立场发生不可逆变化
```

结构完全正确：4 个 beat、有冲突/揭示/代价/转折、有具体物件和地点、结尾是动作。

**语义是空的**——这是设计上接受的取舍（见第 4 节）。
