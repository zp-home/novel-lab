# 02 · AI 写长篇小说的毛病：分层诊断、可量化指标、去味手法

> 配套文档：`01-frameworks.md`（现有框架调研）。本文只回答一个问题：**AI 写出来的长篇，具体坏在哪、怎么用代码量出来、怎么在流水线里修掉。**

## 0. 这份文档怎么用

### 0.1 证据来源分三类，不要混着读

| 标记 | 含义 | 可信度 |
|---|---|---|
| **【实测】** | 本仓库 `novel-lab/samples/` 下 `ai_01.txt`(465 字) 与 `human_01.txt`(294 字) 两份对照样本，用 `novel-lab/src/ai_flavor.py` 跑出来的真实数字 | 数字真实，但样本极小（<500 字），只作**方向性**参考，不作阈值标定 |
| **【文献】** | 已抓到原文的论文/官方公告/百科条目，附链接 | 可直接引用 |
| **【判断】** | 我的工程推断，无外部出处 | 当设计建议看，别当结论引 |

**全文不写"据说""有研究表明"而不给链接。** 抓不到的就不写。第 10 节列了核实状态。

### 0.2 一句话因果链

```
解码选概率均值路径 → 词汇保守、句长收敛、情绪直说、段末升华（A 层）
  → 因为每段都局部最优，整章变成"起承转合"标准件（B 层）
    → 因为上下文衰减 + 无状态机，跨章信息丢失、人物声纹漂移（C 层）
      → 3000 本同一 prompt 采样 → 模式坍缩、撞梗、平台判低质（D 层）
```

**关键认知：A 层是症状，B/C 层是病，D 层是账单。** 只做 A 层的"禁用词替换"能骗过人的第一眼，骗不过第 3 章。

### 0.3 三层防线（后文所有手法都落在这三层）

| 层 | 手段 | 成本 | 能修什么 |
|---|---|---|---|
| **约束层**（生成前/中） | prompt 硬约束、few-shot 风格锚、采样参数、结构化状态注入 | 几乎零边际成本 | A 层大部分、B 层结构、C 层一致性 |
| **后处理层**（生成后，纯代码） | 正则替换、句长重排、段落极化、排版规范化 | 零模型调用 | A 层可枚举项、格式类 |
| **门禁层**（入库前，纯代码） | 统计量打分、跨书去重、台账校验 | 零模型调用 | 全部可量化项、D 层撞梗 |

**核心工程判断【判断】：模型只应该出现在"生成"这一步，其余全部是确定性代码。** 让模型自己"检查有没有 AI 味"，等于让考生自己批卷——而且模型批自己时还有讨好倾向（sycophancy 文献见 A1 与 B3，[arXiv:2310.13548](https://arxiv.org/abs/2310.13548)）。

## 2. A 层：语言层（"AI 味"）

这一层最容易被当成"文笔问题"，其实是**解码策略的统计学后果**。【文献】Holtzman 等人 2019 年的论文原文指出：用似然作为训练目标没问题，但**用似然作为解码目标会产出 "bland and strangely repetitive" 的文本**，人类文本与机器文本存在分布差异（[arXiv:1904.09751](https://arxiv.org/abs/1904.09751)）。A 层八条全部是这个分布差异的表现。

### A1 套式排比与"否定式对举"堆叠

**现象。** 高频句式高度可枚举，不是"语言生硬"这种空话，而是这几条正则能抓住的：

| 中文套式 | 对应英文 AI 指纹 | 例子 | 出处 |
|---|---|---|---|
| 不仅…而且 / 不但…还 / 不仅仅是…更是 | *not only… but also* / *not just X, but Y* | "他不仅看到了荒芜，而且看到了一个时代的落幕" | 【实测】ai_01 |
| 不是…而是 / 不是…是 | *not X, but Y* | "这不仅仅是一片土地的变化，更是一代人命运的缩影" | 【实测】ai_01 |
| 既…又 / 既…也 | — | "他眼中闪过一丝复杂的情绪，既有愤怒，又有不甘，还有深深的疲惫" | [知乎·淡然的鱼](https://zhuanlan.zhihu.com/p/2071744201377818281) 举的 AI 原句 |
| 从…到…（虚假范围） | *from X to Y* | "从解决问题的工具，到科学发现的艺术表达" | [36氪](https://www.36kr.com/p/3824601267196037) 举的"虚假范围"例 |
| 三段式并列（A，B，C。） | *rule of three* | "他深吸一口气，缓缓开口，声音中带着一丝不易察觉的颤抖" | 【实测】ai_01 |

【文献】维基百科 WikiProject AI Cleanup 维护的 *Signs of AI writing* 把 "Negative parallelisms"（Not just X but also Y / Not X but Y / Y rather than X）和 "Rule of three" 单列为独立条目，并给出大量带 diff 链接的真实案例（[Wikipedia:Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)）。中文侧，36氪《消除"罪证"：给写作去除"AI味"的不完全手册（2026版）》也把"否定式煽情句式""虚假范围"列为最典型的两类（[36kr](https://www.36kr.com/p/3824601267196037)）。

**成因（机制层）。** 三层叠加：
1. **解码层**：贪心/低温度解码总选条件概率最高的续写，"不仅…而且"这类关联词对在训练语料里是高置信搭配，模型一旦写出"不仅"就几乎必然续"而且"。
2. **RLHF 层**：对举结构天然显得"有思辨、有深度"，人类标注员偏好它，奖励模型把它学成了"好答案"的通用标志。这不是猜测——【文献】Sharma 等人在 *Towards Understanding Sycophancy in Language Models* 中实测到：当回答迎合用户观点时更可能被偏好，而且人类和偏好模型都会以"不可忽略的比例"偏好**写得更有说服力的谄媚回答**而非正确答案（[arXiv:2310.13548](https://arxiv.org/abs/2310.13548)）。
3. **段落级局部最优**：对举结构是"一句话内闭合"的，写起来不需要跨段信息，所以段级最优解永远选它。

**可检测信号。**
- 强模式密度 `D_par_strong = (count("不仅…而且") + count("不是…而是") + count("既…又")) / 千字`。
- 弱模式密度 `D_par_weak`（三段式并列）：**注意这个指标假阳性极高**，见 A9 的校准陷阱。
- 一篇文本内"对举句式种类数"——AI 往往反复用同 2–3 种。

### A2 万能副词 / 万能形容词"糊墙"

**现象。** 中文网文圈已经有公认的禁用词清单，不需要发明，直接照抄就能命中：

> 仿佛、似乎、不禁、不由得、缓缓、微微、轻轻、悄然、默默、一丝、一抹、一缕、几分、些许、隐约、恍惚、若有所思、意味深长、深吸一口气、缓缓开口、沉默片刻、良久、叹了口气、苦笑一声、眼神复杂、心中涌起、心头一震、五味杂陈、百感交集、如遭雷击、难以言喻、不知为何、与此同时、终于明白、恍然大悟、一切都不一样了、无尽的、深深的、淡淡的、莫名的、前所未有的、令人窒息的

这份表不是我编的，`novel-lab/src/ai_flavor.py` 的 `AI_CLICHE` 常量里就有 100+ 条，可以直接 import。

【实测】**`ai_01.txt` 的套话密度 53.76 处/千字，`human_01.txt` 是 0.00 处/千字。** 465 字的样本里命中 25 处，其中 `缓缓`×3、`仿佛`×2，还有 `时间仿佛静止`、`复杂的情绪`、`不易察觉`、`终于明白` 各 1 处。

**成因。** 这是 A 层里"纯解码"性质最强的一条。这些词是**高概率低信息量的通用润滑剂**：无论上下文是什么，"缓缓地"都有不低的概率接在动词前，"一丝"都有不低的概率接在情绪名词前。模型不需要理解场景就能安全地输出它们——所以它们是**风险最低的选择**，而低风险选择在采样时被反复选中，形成正反馈。

另一个机制是**副词补偿**：模型对动作的把握是模糊的（它没有身体），所以用"缓缓地""轻轻地"来给动作加质感，而不是写出动作本身的差异（"他把烟按进烟灰缸"vs"他慢慢地把烟放进烟灰缸"）。

**可检测信号。**
- 套话密度 `D_cliché`（词表命中数 / 千字）。
- 副词化率 `R_adv = 副词命中数 / 动词性短语数`（粗算可用"地"字密度代替）。
- **万能形容词多样性**：万能形容词的总出现次数 / 其类型数。AI 会反复用同样那几个（"复杂的""莫名的"），人写的形容词更分散。

### A3 情绪"直说"而非"呈现"

**现象。** 直接命名情绪，而不是写可观测的行为后果。

| AI 写法（tell） | 人写法（show） | 出处 |
|---|---|---|
| 他感到一阵难以言喻的酸楚，眼眶微微发热。 | 他伸手去拧钥匙，手指停在半空。 | 【实测】ai_01 / human_01 同一场景对照 |
| 心里五味杂陈 | 他把化肥往地上一撂，走过来，手在裤腿上蹭了两下。 | 【实测】ai_01 / human_01 同一场景对照 |
| 他眼中闪过一丝复杂的情绪，既有愤怒，又有不甘，还有深深的疲惫。 | 他盯着那边看了两秒，嘴角动了动，最终什么都没说，只是把烟按进了烟灰缸。 | [知乎·淡然的鱼](https://zhuanlan.zhihu.com/p/2071744201377818281)（原文为"AI 原句可能是…改成…"的改写示例） |

【实测】**`ai_01` 情绪直说密度 15.05 处/千字，`human_01` 是 0.00。** 命中词包括 `心中`×2、`心里`×1、`感到`×1、`感到一阵`×1、`情绪`×1、`惊讶`×1。

**成因。** 三个机制：
1. **情绪词是"安全的高概率续写"**：给定"他看到二叔眼中的惊讶"，模型知道此处该有情绪反应，"他感到一阵酸楚"是语料里出现频率最高的写法。
2. **模型没有身体**：呈现情绪需要写"手指停在半空""手在裤腿上蹭"这种身体细节，这些细节在训练语料里是**低概率、长尾、需要具体场景知识**的。模型的先验是"抽象优于具体"。
3. **讨好倾向**：直说情绪让读者"立刻懂"，呈现情绪要求读者自己推断。RLHF 偏好"立刻懂"的回答。

**可检测信号。**
- 情绪直说密度 `D_tell`（`感到/觉得/心中/心里/内心/情绪/心情/心头` + 情绪形容词表命中数 / 千字）。
- **情绪词与身体动作的比例**：`N(情绪词) / N(身体部位词 + 动作词)`。人写这个比值显著低。
- 每个情绪段落里"可观测动作"的数量：AI 段落常常是 0。

### A4 每段结尾升华（"上价值"）

**现象。** 段落最后一句从叙事切到议论/抒情，把具体事件拔高成抽象命题。

真实高频收尾模板：
- "他知道，无论走多远，这里永远是他的根。"【实测·ai_01】
- "这一刻，他终于明白，有些东西一旦失去，就再也回不来了。"【实测·ai_01】
- "命运的齿轮从未停止转动，而他，终究只是这洪流中一粒微不足道的尘埃。"【实测·ai_01】
- "这不仅仅是一片土地的变化，更是一代人命运的缩影。"【实测·ai_01】

【实测】**`ai_01` 段末升华率 0.364（11 段里有 4 段以升华句收尾），结尾升华标记 1.0（末段命中"命运/注定"类词）；`human_01` 两项都是 0.000。**

**成因。** 这是"段落级局部最优"最典型的产物。模型在生成一个段落时，末尾的 token 位置有强烈的**收束压力**——训练语料里段落的最后一句经常是总结性的，所以"总结"成了段落结束的默认动作。它没有"这一章还有下文所以此处不该收束"的概念，因为它在段级别优化，不在章级别优化。

【文献】维基百科条目把这类现象命名为 "Undue emphasis on significance, legacy, and broader trends"，并指出 LLM 会"puff up"平凡主题的重要性，连词源、人口数据这种琐碎条目都要扯到"更广泛的趋势"（[Wikipedia:Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)）。中文侧的对应现象就是"每段都要上价值"。

**可检测信号。**
- 段末升华率 `R_sub`：段末句含升华词（命运/意义/人生/灵魂/永恒/宿命/救赎/人性/尊严/价值/本质/真相/自由/孤独/成长/选择/希望/未来/世界/一切/永远/从此/注定/轮回/羁绊/传承/时代）且句长 ≤40 字，则计 1；除以段数。**健康值 ≤0.10。**
- **段末/段首长度比** `r = mean(len(段末句)) / mean(len(段首句))`。人写 ≈1.0–1.2，AI 明显 >1.5（因为段末句要"铺开议论"）。【实测】ai 1.66 / human 1.20。
- 末段升华标记：末 2 段是否命中升华词。

### A5 句长收敛：节奏"平权"

**现象。** 句子长度集中在 16–25 字，没有极短句，没有长复句。

【实测】两份样本的句长分布对照：

| 指标 | `ai_01` | `human_01` |
|---|---|---|
| 句长均值 | 16.61 字 | 10.89 字 |
| 句长中位数 | **18 字** | **6 字** |
| 句长 CV（变异系数） | **0.519** | **0.957** |
| ≤8 字短句占比 | 0.214 | **0.519** |
| 16–25 字的句子数 | 14 / 28 句（50%） | 3 / 27 句（11%） |
| 25/50/75/90 分位 | 10 / 18 / 23 / 26 | **3 / 6 / 13 / 28** |

看最后一行：**人写的句长 90 分位是 28 字，是 50 分位（6 字）的 4.7 倍；AI 的 90 分位 26 字只有 50 分位（18 字）的 1.4 倍。** 人的句子是"极短—极长"跳跃，AI 的句子是一个窄带。

**成因。** 这就是 burstiness 塌陷。【文献】Holtzman 的论文核心结论是：人类文本的句子在"惊讶度"上剧烈波动，机器文本平滑（[arXiv:1904.09751](https://arxiv.org/abs/1904.09751)）。机制上：长句需要跨句信息组织（模型在多句尺度上是弱项），短句需要"敢留白"（模型倾向于把话说完整），所以中长度句是唯一的安全区。

**可检测信号。**
- 句长 CV（见 8 节 M1）。
- 短句占比（M2）。
- 相邻句长落差的均值（M3）。
- **句长分布的 90 分位 / 50 分位比**，健康 ≥2.5。

### A6 对话像论文答辩

**现象。** 每个角色说话都是完整、礼貌、信息量对等的长句；没有打断、没有跑题、没有答非所问、没有说话人自己都不知道自己在说什么。

对比【实测】：

| | `ai_01` | `human_01` |
|---|---|---|
| 对话占比 | 0.054 | 0.119 |
| 对话轮数 | 6 | 9 |
| 每轮字数 | [3, 1, 12, 5, 2, 2] | [3, 12, 1, 5, 2, 2, 3, 4, 3] |

两份样本的对话都短，但**人写的对话占比是 AI 的 2.2 倍，轮数多 50%**；且人写的 12 字长台词承载的是信息（"你妈坟上的草，我上礼拜割了"），AI 的 12 字长台词承载的是情绪解释（"声音沙哑而温和，像是从很远的地方传来"）。

典型 AI 对话病灶【判断，四条均为阅读归纳，非统计结论】：
- 双方都完整回答问题，没有一方"接不住"。
- 每句话都在推进信息，没有一句是纯粹的废话/寒暄/情绪噪音。
- 所有角色用同一套词汇和句长（**声纹不分化**）。
- 关键信息由角色"说出来"而不是由读者"看出来"。

**成因。** 对话是**多智能体博弈**的产物，而单模型生成对话时是**单智能体顺序预测**——它同时"扮演"所有人，于是所有人的语言风格向同一个均值收敛。另外，模型有强烈的"信息完整"倾向（把话说清楚是 RLHF 奖励的），所以它不会写"说了半句被打断"。

**可检测信号。**
- 对话占比 `R_dlg`（引号内汉字数 / 总汉字数）。中文网文健康区间约 0.25–0.45，<0.12 明显偏少。
- **对话轮长 CV**：健康 ≥0.70，且 ≤3 字的极短轮占比 ≥0.15。
- **角色声纹散度**：对每个角色抽取其台词，构造字 2-gram 分布，两两算 Jensen-Shannon 散度。健康 ≥0.30 nat（需按题材标定）。AI 写的对话这个值通常 <0.15。
- 对话中"未完成句"（以"……"或"——"结尾的轮次）占比：AI 常为 0。

### A7 万能比喻与成语堆砌

**现象。** 比喻只用"像/如同/仿佛/宛如/犹如"这几个词，喻体高度同质（"如同一道闪电""如同一记重锤""仿佛整个世界都安静了""仿佛时间静止"——这几个串在 `ai_flavor.py` 的 `AI_CLICHE` 里就是按"套路比喻"单列的）；四字格（成语/熟语）密度过高，把叙事写成了骈文。

【实测】比喻词密度：`ai_01` 8.60/千字，`human_01` 3.40/千字（2.5 倍）。四字格密度：ai 2.15/千字，human 3.40/千字——**注意这条反了**，说明"成语多"本身不是可靠信号，可靠的是**成语的集中度**（同一段里连用 3 个以上）。

**成因。** 喻体选择是典型的长尾问题：好的喻体来自作者的个人经验库（"白色颗粒从缝里漏，落在地上像一层霜"），而模型的喻体来自训练语料的高频共现（"如同一道闪电"跟"划过"共现了上百万次）。模型不是不会创新喻体，是**创新喻体的概率被高频喻体压死了**。

**可检测信号。**
- 比喻词密度 `D_sim`。
- **喻体类型数 / 比喻总数**（多样性）。AI 常低于 0.5。
- 四字格**同段连用**次数：同一段内 ≥3 个四字格即计一次违规。

### A8 抽象大词替换具体器物

**现象。** 用"命运/意义/灵魂/存在/自由/孤独/救赎/真相/人性/尊严/价值/本质/永恒/羁绊"这类大词承载情绪，而不是用碗、筷子、化肥袋、水温表、锈钢筋。

【实测】具象词密度：`ai_01` 49.46/千字，`human_01` **108.84/千字**（2.2 倍）。抽象大词密度：ai 6.45/千字，human 0.00/千字。

人写样本里的具象细节：`半袋化肥，袋子破了个口，白色颗粒从缝里漏` / `柴油味和汗味，还有一点劣质烟草的焦味` / `水温表的指针停在中间，一动不动` / `几根钢筋从土里伸出来，锈成红褐色`。AI 样本里同类位置写的是：`心中涌起一股莫名的悲凉` / `一个时代的落幕` / `一代人命运的缩影`。

**成因。** 具象词是**低频、需要世界知识、且必须与场景严格匹配**的。写"水温表指针停在中间"要求模型知道车熄火后水温表的行为；写"化肥袋破了个口，白色颗粒从缝里漏"要求它知道尿素是白色颗粒。这些知识的条件概率远低于"心中涌起一股悲凉"，所以采样时具象词被系统性压制。

【文献·译者自译】维基百科条目用一句话概括了这个机制，原文是："the LLM tends to omit specific, unusual, nuanced facts (which are statistically rare) and replace them with more generic, positive descriptions (which are statistically common)"——即模型倾向于省略具体的、不寻常的、细微的事实（统计上罕见），改用更通用的、正面的描述（统计上常见）（[Wikipedia:Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)，"Content" 节）。

**可检测信号。**
- 具象词密度 `D_con`（器物/身体/天气/动作词表命中数 / 千字）。
- 具象/抽象比 `R_ca = (D_con + 0.5) / (D_abs + 0.5)`。**加 0.5 平滑是必须的**——`human_01` 的抽象词密度是 0，不平滑会算出无穷大（实测原版脚本就报出了 1088.4 这个荒谬值）。
- 每场景"新具象名词"数（去重后）：AI 常 <5，人写常 >10。

### A9 指标校准陷阱（重要，别跳过）

跑完对照后有四个指标**方向反了或不可用**，必须记下来，否则门禁会误杀：

| 指标 | `ai_01` | `human_01` | 脚本内参考区间 | 问题 |
|---|---|---|---|---|
| 套式排比密度（含三段式） | 8.60 | **17.01** | 人写 0.6 / AI 4.5 | **三段式正则假阳性极高**——人写的"远处有人烧秸秆，烟斜着飘过来，糊在挡风玻璃上"被误判成排比 |
| 句首多样性 | 0.947 | **0.875** | 人写 0.88 / AI 0.68 | 294 字 / 27 句的样本上不稳定，需 ≥200 句才有统计意义 |
| 标点熵 | 1.182 | 1.118 | 人写 2.3 / AI 1.8 | 短文本标点种类少，熵必然低，参考值不适用 |
| 对话句长 CV | 0.892 | 0.790 | 人写 0.85 / AI 0.45 | 6–9 轮对话算 CV 无统计意义 |

**三条结论：**
1. **强模式（不仅…而且 / 不是…而是 / 既…又）与弱模式（三段式并列）必须分开计权**，弱模式权重 ≤1/3，且必须人工抽检 20 条确认精确率。
2. **所有指标必须按字数分档标定**：<1000 字、1000–5000 字、>5000 字三档，阈值不能共用。
3. **参考区间必须用真实人写语料重标定，不能抄别人的**。`ai_flavor.py` 里的 `human_ref` 是初始值，`human_01` 一份 294 字样本就已经让四个指标失效。

## 3. B 层：结构层

A 层决定"读两段会不会出戏"，B 层决定"读完一章记不记得住任何事"。

### B1 每章一个"起承转合"模板块

**现象。** 打开任意一章，骨架几乎一样：

```
场景铺陈（环境+人物出场，150–250 字）
  → 冲突/疑问出现（200 字）
    → 交锋/推进（300–400 字）
      → 化解 + 一句升华收尾（100–150 字）
```

模板本身不是错，错在**每一章都是它，且各段字数配额几乎相同**。真实的长篇会有"整章都是对话""整章都是回忆""这一章什么都不发生"。

**成因。** 生成时模型按"章节"这个粒度做条件生成，而训练语料里的章节绝大多数是完整闭环的（网文的章末要有钩子，但也要有本节的完成感）。模型学到的是**章级模板的先验**，而它没有"这一章应该反模板"的元认知。

**可检测信号。**
- **章内 beat 序列的熵**：把每章按 1/8 切段，用功能词典（开场/冲突/揭示/转折/代价/收束）给每段打标，得到 8 位功能串；统计全书功能串的分布，`H = −Σ p log2 p`。**3000 本规模下，最常见的功能串占比 >0.35 即判坍缩。** `novel-lab/src/diversity.py` 的 `structure_fingerprint()` 已经实现了这个打标。
- **章内四段字数配额的方差**：如果所有章都是 20%/20%/40%/20%，方差接近 0，直接报警。

### B2 危机必解决（无悬念留存）

**现象。** 本章制造的危机在本章内解决；章末不留"未解决且读者在意"的问题；即使留了钩子，下一章开头也会立刻解释清楚。

**成因。** 两个机制叠加：
1. **训练语料的章节大多自洽**（网文章节确实是"小闭环"），模型学到的先验就是闭环。
2. **模型有强烈的"完成感"倾向**——留悬念意味着输出在语义上"不完整"，而模型被训练成产出完整的回答。这和 RLHF 的"有用性"奖励直接冲突。

**可检测信号。**
- **章末未解决冲突数** `U`：抽取章末 200 字里的疑问/威胁/未达成目标，人工或规则标注，健康 ≥1。
- **钩子存活率**：第 N 章末的钩子，在第 N+1 章前 30% 内是否被"解释掉"（而不是"推进"）。存活率 = 推进数 / (解释数 + 推进数)。健康 ≥0.6，AI 常 <0.2。
- 规则近似：章末句是否含"终于/明白了/解决了/松了一口气"这类闭合词。

### B3 无真正代价

**现象。** 主角不失去任何不可逆的东西。受伤会好，钱会赚回来，死的人能复活，背叛的人会洗白。所有"代价"都是可逆的、可补偿的。

**成因。** 这是 RLHF 讨好倾向在**叙事层**的直接投影。【文献】sycophancy 论文的实测结论是：当回答迎合用户观点时更可能被偏好；而且**人类与偏好模型都会以"不可忽略的比例"偏好写得更有说服力的谄媚回答，而非正确答案**；拿偏好模型做优化有时会以牺牲真实性为代价换取讨好（[arXiv:2310.13548](https://arxiv.org/abs/2310.13548)）。"主角断了一条腿并且永远好不了"是令人不满意的回答；"主角受了重伤但突破了境界"是令人满意的。奖励模型学到的就是这个。

**可检测信号。**
- **不可逆损失事件数**：全书里"损失发生后再未恢复"的事件数。5000 字短篇健康 ≥1，AI 常为 0。
- **损失/补偿比**：`N(损失事件) / N(补偿事件)`。若每个损失后面都跟着补偿，比值 ≈1，报警。健康 ≥2。
- 数值单调性检查：能力值/财富/地位曲线是否**单调不降**。单调不降 = 无代价。

### B4 节奏平权（每段信息量相同）

**现象。** 没有"详写"和"略写"的区别。一场决定性战斗和一次吃饭，字数差不多，句子密度差不多。该用 300 字写的转折，用了 80 字；该用 1 句话带过的过渡，用了 400 字。

**成因。** 模型没有"重要性"的连续度量，只有 token 级的局部概率。它无法判断"这个事件在全书中的权重"，所以默认按"每个事件都值得写 200 字"来分配。

【文献】CONCOCT 论文（EMNLP Findings 2023）专门解决这个问题：训练一个"具体度评估器"判断两个事件哪个更具体，用它在分层大纲里做 vaguest-first 扩展，追求**均匀节奏**——这反过来说明，模型默认的节奏是**不均匀且不受控**的（`01-frameworks.md` 已收录该论文，arXiv:2311.04459）。

**可检测信号。**
- **章内段落长度熵** `H_para = −Σ p_b log2 p_b`（b = 段长分桶 ≤15/16–40/41–80/>80）。【实测】`ai_01` 分布 {≤15:4, 16–40:2, 41–80:3, >80:2} → **H=1.936 bit**；`human_01` {≤15:12, 16–40:2, 41–80:3} → **H=1.160 bit**。**注意：这条在本样本上人写更低**，因为人写样本更"极化"（大量 1–10 字短段 + 少量 40+ 长段），而熵衡量的是均匀度——**AI 的段落长度反而更"均匀地铺开"**。所以 B4 **不要用熵**，用下面的双峰指标。
- 更好的指标：`R_short_para = |{段长 ≤15}| / 段数`，健康 ≥0.40；`R_long_para = |{段长 ≥80}| / 段数`，健康 ≥0.08。两者同时满足 = 段落极化。【实测】ai **(0.364, 0.182)** / human **(0.706, 0.000)** —— 人写样本极短段极多（17 段里 12 段 ≤15 字），ai 的长段偏多且短段不足。
- **场景字数方差**：同一本书内各场景字数除以全书字数，方差应 ≥0.02。

### B5 伏笔埋而不收 / 收了没埋

**现象。** 两种方向都常见：
- **埋而不收**：前文给了明确的物/信息/承诺，后文完全不提。读者等了 4000 字，没等到。
- **收了没埋**：结尾突然出现一个"关键道具/关键人物"，但前文从没出现过——这是**更严重**的，因为它让读者觉得自己白读了。

**成因。** 埋而不收是**上下文衰减**的后果：埋点的信息在第 3 章，收在第 8 章，中间隔了 2.5 万字，如果不用结构化状态记录，这个信息在生成第 8 章时已经不在有效上下文里了。【文献】Liu 等人的 *Lost in the Middle* 实测到：模型对长上下文中间位置的信息利用显著退化，性能在相关信息位于开头或结尾时最高，位于中间时最差（[arXiv:2307.03172](https://arxiv.org/abs/2307.03172)）。

收了没埋是**讨好倾向**的后果：结尾需要一个"震撼的揭晓"，模型就直接造一个，不管前文有没有铺。

**可检测信号。**
- **伏笔回收率** `R_fb = 已回收伏笔数 / 已登记伏笔数`。5000 字短篇必须 =1.0，没有例外。
- **无源揭示数**：结尾 20% 内出现的关键名词（人名/物名/地名），在前 80% 中的出现次数为 0 的个数。健康 =0。
- 实现方式：大纲阶段给每个伏笔分配 ID + 埋点章 + 回收章，正文生成时用 ID 锚定，门禁用正则/实体匹配校验。

### B6 配角工具人

**现象。** 配角只在需要他的功能时出现：需要有人递话就出场，需要有人被杀就出场，需要有人解释设定就出场。没有自己的欲望、口头禅、时间线。名字常常是"二叔""老王""那个男人"这种功能性称呼。

**成因。** 单模型生成时，所有角色的"意图"都由同一个分布产生，配角的意图被主角的意图支配。模型没有"这个角色此刻想要什么"的独立状态——除非你显式给它一个。

**可检测信号。**
- **配角台词轮数分布**：配角台词轮数 / 主角台词轮数。健康 ≥0.3；AI 常 <0.15。
- **配角主动发起事件数**：配角发起（而非回应）的对话/行动次数。健康 ≥1/配角。
- **配角专属词**：只在该配角台词里出现的词（2-gram）数量。健康 ≥3；AI 常为 0（所有人用同一套词）。

### B7 时间线漂移

**现象。** 场景内时间不推进（三个人对话说了 2000 字，天色一直是"傍晚"），或者突然跳跃（"三天后"用了两次但实际只过了一天），或者时间标记互相矛盾（"天刚亮"→ 500 字后 → "夕阳西下"但事件只够 20 分钟）。

**成因。** 模型对"时间"没有内部时钟，它只有"时间词"的概率分布。"天色渐渐暗了下来""与此同时""片刻后"这些是**装饰性时间词**，不承担真实的计时功能。所以它能写出时间词，但写不出时间一致性。

**可检测信号。**
- **场景时间标记密度**：每个场景（约 500–800 字）应至少有 1 个可解析的时间标记（"天刚亮/正午/傍晚/晚上九点/第二天"）。AI 常整章只有开头一个。
- **时间单调性检查**：把所有时间标记按出现顺序解析成相对时刻（可用 LLM 抽取一次，然后纯代码校验），检查是否严格递增。违反即报警。
- **装饰性时间词占比**：`(突然+与此同时+片刻+良久+终于) / 全部时间词`。这个比例越高，说明时间越"假"。健康 ≤0.4。【实测】`ai_01` 时间推进词密度 4.30/千字，`human_01` 是 **0.00**/千字——人写样本完全不靠时间词推进，靠事件本身。

## 4. C 层：一致性层

C 层是唯一"读者会真的生气"的一层。A 层让人觉得"不好看"，C 层让人觉得"被骗了"。

### C1 人物 OOC（声纹漂移）

**现象。** 同一个角色，第 1 章说话简短粗鲁，第 5 章变得文雅冗长；或者更隐蔽——**所有角色都在向同一个"作者声音"收敛**，读起来像一个人在自言自语。

**成因。**
1. **上下文衰减**：角色的早期台词在第 5 章时已经不在有效上下文里（*Lost in the Middle*，[arXiv:2307.03172](https://arxiv.org/abs/2307.03172)）。
2. **均值回归**：模型的默认输出是"平均风格"，除非被强约束，否则每个角色的台词都会被拉向这个均值。这是 "regress to the mean" 在角色层的表现——【文献·译者自译】维基百科条目的原文是："It thus tends to regress to the mean; that is, the result tends toward the most statistically likely result that applies to the widest variety of cases."（[Wikipedia:Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing)）

**可检测信号。**
- **角色声纹 JS 散度**（见 A6）。这是 C 层最重要的单一指标。
- **角色台词句长均值差异**：不同角色的台词平均句长应该有差异，`max(μ_i) / min(μ_i)` 健康 ≥1.5。
- **角色口头禅命中率**：给每个角色登记 3 个专属词/句式，检查其在全书中的命中密度是否稳定。

### C2 称谓 / 年龄 / 亲属关系漂移

**现象。** 同一个人一会儿"二叔"一会儿"二伯"；人物年龄前后差 5 岁；"表哥"变成"堂哥"；长辈突然用平辈语气说话。

**成因。** 中文称谓是一个**高基数、低频率、强关系约束**的封闭集合。模型知道"二叔"是常见称谓，但不知道本书里这个人已经被固定叫"二叔"了——除非状态里写着。而且称谓在语料里常常混用（不同作者用法不同），模型学到的是"这些称谓都可用"。

**可检测信号。**
- **称谓熵**：对同一实体，统计其被称呼的所有形式及频次，`H = −Σ p log2 p`。健康 =0（一本书里一个实体只有一种称呼），>0 即报警。
- **实体-属性冲突率** `R_conf`：从正文抽取三元组（实体，属性，值），与状态圣经比对，冲突数 / 总断言数。健康 <0.02。
- 实现：用一次 LLM 抽取建状态圣经，之后全部用规则/字符串匹配校验——不要每次都用 LLM 校验（成本 + 不一致）。

### C3 地理 / 空间漂移

**现象。** 上一章主角在县城，这一章没写移动过程就出现在省城；村口的地形前后不一样；"往东走"走到了西边的镇。

**成因。** 空间关系在语言模型里是**弱表征**的。模型能生成"他往东走"，但它的"东"不绑定任何坐标系。跨章的空间一致性需要显式的世界地图数据结构，模型自己不会维护。

**可检测信号。**
- **地点转移缺过程率**：相邻场景地点不同，但中间没有移动动词（走/坐车/飞/传送）的比率。健康 =0。
- **地点集合一致性**：全书出现的所有地名是否都在设定圣经的地名表里。出现新地名即报警（需要人工确认是有意新增还是幻觉）。
- 方位词冲突：同一地点被赋予互斥方位描述的比率。

### C4 能力值膨胀与数值不自洽

**现象。** 战斗力/等级/财富/人数，随着章节数单调膨胀，且膨胀速度不受控；或者前后矛盾（第 3 章"他有三千人马"，第 6 章"他手里只有八百人"，中间没有损失事件）。

**成因。** "升级"是网文最强的爽点信号，也是最容易被奖励的。模型学到"越往后数值越大"的先验，于是**无约束地通胀**。同时它没有算术能力来校验"三千减两千等于八百"这种账。

**可检测信号。**
- **数值单调性**：把全书所有可抽取的数值按实体分组，检查是否单调不减。若单调不减且无损失事件 → 膨胀报警。
- **数值复利**：`value_last / value_first`。5000 字短篇健康 ≤10；AI 常出现 >100 的跳跃。
- **算术一致性**：抽取"总数 - 损失 = 剩余"型断言，用代码验算。AI 的算术错误率在长文本里显著上升。

### C5 设定自相矛盾

**现象。** 世界观规则被自己违反。典型：设定"魔法需要吟唱"，第 4 章主角默发；设定"这个世界没有电"，第 6 章出现"电灯"；设定"死人不能复活"，第 8 章复活了。

**成因。** 设定规则是**长程约束**，而模型在生成第 8 章时只看到了第 7 章的上下文。而且模型有强烈的"当下叙事需求"倾向——第 8 章需要一个震撼场面，它就造一个，不管是否违反前面的规则。

**可检测信号。**
- **规则违反数**：把世界观规则写成可判定的断言（"若 X 则 Y"），在正文中检索反例。规则集 20–50 条，纯正则 + 关键词即可覆盖 60%。
- **设定断言冲突率**：同 C2 的 `R_conf`。
- **平台参考**【文献】：番茄小说 2026-05-22 公告把"结构失常"（梗概式写文、开篇结尾句式重复堆砌、模板化拼接）与"空洞水文"（机械罗列时间动作对话的流水账、长篇幅无实质情节推进、堆砌艰涩概念）列为独立违规类型，并明确处置梯度为"拒绝签约 / 减少分发 / 限制更新 / 下架整改 7 天或 30 天 / 永久"（[番茄官方公告 2026-05-22](https://fanqienovel.com/writer/zone/article/7642544663915675672)）。设定矛盾本身不直接对应某一类，但它是"缺乏原创性、逻辑性"的组成部分。

### C6 上一章的事忘了

**现象。** 上一章刚发生的事，这一章完全没提；上一章刚认识的人，这一章像第一次见；上一章受的伤，这一章没了。

**成因。** 纯粹的上下文窗口问题。5000 字短篇一次能装下，但 30 万字长篇必须靠外部状态。所有"滚动摘要"方案的根本缺陷是：**摘要是有损压缩，且压缩时不知道未来会用到什么**。【文献】DOME 用**时序知识图谱**做记忆（arXiv:2412.13575），ConWriter 用**场景级增量状态 + 叙事转移检查**（arXiv:2608.05169），都是在把"摘要文本堆"换成"结构化状态"——`01-frameworks.md` 第 3 节有详细对比。

**可检测信号。**
- **状态遗忘率**：上一章结束时处于"活跃"状态的所有实体（在场的人、持有的物、未解决的冲突），在本章前 30% 内被提及的比率。健康 ≥0.8。
- **重复介绍率**：已被介绍过的实体（人名/地名）被以"介绍性句式"（"一个叫 X 的人""这里是 Y"）再次引入的次数。健康 =0。
- **伤害/状态延续**：上一章的伤害/负面状态在本章是否被承认。健康 ≥1。

## 5. D 层：商业 / 合规层

这一层的成本最高：A/B/C 层是"不好看"，D 层是"白干 + 封号"。

### D1 同质化撞梗（模式坍缩）

**现象。** 3000 本书，同一个题材，同一个 prompt 模板，结果：开局都是"退婚/被赶出家门/捡到戒指"，金手指都是"系统/老爷爷/空间"，第一个打脸桥段都在第 3 章，结局都是"登顶"。

**成因。** 这是 **model collapse** 的工程版。【文献】Shumailov 等人的 *The Curse of Recursion* 指出：使用模型生成内容训练会导致不可逆缺陷，**原始内容分布的尾部消失**（"tails of the original content distribution disappear"），并称之为 Model Collapse（[arXiv:2305.17493](https://arxiv.org/abs/2305.17493)）。3000 本同一 prompt 采样不是训练坍缩，但机制同源：**采样的多样性被"最高概率路径"系统性侵蚀**，每次采样都落在分布的同一个高密度区域。

**可检测信号。** `novel-lab/src/diversity.py` 已经实现了完整方案，直接可用：
- 每本书三个指纹：字符 4-gram MinHash（128 维）、意象 2-gram 集合 Jaccard、结构功能序列（8 位）。
- 两两相似度 `combined = 0.45·minhash + 0.30·imagery_jaccard + 0.15·structure + 0.10·opening`。
- **判级：平均两两相似度 <0.20 OK；0.20–0.35 WARN；>0.35 BAD（同批书互相可替代）。**
- 附加信号：最常见结构功能串的占比（>0.35 即坍缩）、开头 60 字指纹重复率。

### D2 抄袭 / 洗稿风险

**现象。** 两种风险：
- **对外撞车**：生成内容与已有作品高度相似（训练数据记忆 + 高频桥段）。
- **对内撞车**：3000 本之间互相抄袭（同一批模板采样）。

**成因。** 前者是训练数据记忆，后者是 D1 的直接后果。**对工业流水线来说，对内撞车的风险远大于对外**——因为对外的相似度通常达不到"实质性相似"，而对内的相似度可以轻松达到 0.5+。

**可检测信号。**
- 对内：D1 的 MinHash 相似度矩阵，任意两本 `combined > 0.35` 即拦截重采样。
- 对外：4-gram 精确匹配（与已出版作品库比对），连续 13 字以上完全相同的片段数。健康 =0。
- **桥段指纹**：把"退婚/捡宝/打脸/认亲/复仇"等桥段编码成事件序列，跨书比对序列相似度（编辑距离）。这一层比 n-gram 更能抓住"洗稿"。

### D3 平台 AI 检测（番茄 / 起点 / 知乎）

**现象。** 平台判定"AI 粗制滥造"，拒绝签约、限流、下架。

**平台规则（已核实原文）**：
- 番茄小说 2026-02-04 公告：重点整治"滥用 AI 工具批量生成、拼凑内容，作品缺乏原创性、逻辑性，语言生硬、内容空洞，属于'粗制滥造'范畴"；处置为"拒绝签约、内容限流、下架直至永久封禁"；该次专项处置违规账号 **855 个**（[官方公告](https://fanqienovel.com/writer/zone/article/7602950185735438398)）。
- 番茄小说 2026-05-22 公告：明确四类低质（**AI 粗制滥造 / 格式混乱 / 结构失常 / 空洞水文**），5 月以来"拒绝签约低质书籍 **112706** 本，处置低质违规书籍 **40275** 本"（[官方公告](https://fanqienovel.com/writer/zone/article/7642544663915675672)）。
- 起点/阅文：阅文作家专区"投稿给编辑"页面写明拒绝 AI 生成内容，查实后无法签约；《起点读书用户服务协议》13.4 条要求对生成式 AI 制作的非真实信息"以显著方式予以标识"，否则平台可增加标识、限制、封禁。【文献·二手整理，附核对日期】[马良写作·番茄起点 AI 内容规则](https://maliangwriter.com/guides/platforms/ai-content-policy/)
- 知乎：《关于 AI 生成合成内容标识的公告》（知乎小管家，2025-08-30）——依据《人工智能生成合成内容标识办法》推出标识功能，发布路径为「发布设置 → 创作声明 → 包含 AI 辅助创作」，要求创作者"积极对 AI 生成内容进行标注声明"（[知乎官方公告](https://zhuanlan.zhihu.com/p/1945129544358028875)）。**注意：知乎是内容社区不是网文签约平台，它管的是"声明"，不是"签约资格"。**

**检测技术（二手，可信度中等）**：一篇二手技术解析称番茄的风控包含四层——统计指纹层（困惑度方差、词熵衰减斜率、突发性 n-gram 比率）、语义判别层（DeBERTa-v3-large 微调，F1@0.5 = 0.892）、行为水印层、闭环反馈层；另有报道称"AI 特征值超过阈值（如单章超 60%）触发预警限流"。这些数字我**没有拿到一手来源**，只作为设计参考，不要当官方口径引用（[什么值得买转载](https://post.smzdm.com/p/a0324oxz/)）。

**可检测信号（工程上要做的）**：
- 直接对齐平台口径的四类：AI 粗制滥造（原创性指标）、格式混乱（排版检查）、结构失常（B 层指标）、空洞水文（信息密度指标）。
- **信息密度** `ρ = 事件数 / 千字`。这是"空洞水文"最直接的可量化定义。健康 ≥2.0；AI 常 <1.0。
- **新信息率**：本章出现的新实体/新设定/新冲突数 / 本章字数。健康 ≥1/500 字。

**关键合规判断**【判断】：番茄的原文是"滥用 AI 工具**批量生成**、**严重缺乏原创性**"，不是"AI 参与即违规"。所以**合规的边界不在"用不用 AI"，在"原创性是否可举证"**——这直接决定了流水线必须保留生成参数、大纲、改写记录作为自证材料。

### D4 生成式内容标识合规（中国境内）

**现象。** 发布 AI 生成内容未做标识，平台侧有合规风险。

**规则（已核实原文）**：《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号，国家网信办、工信部、公安部、广电总局联合印发，**2025 年 9 月 1 日起施行**）。要点：
- 第三条：标识分**显式标识**（用户可明显感知）和**隐式标识**（文件元数据中的技术措施）。
- 第四条：文本需"在文本的起始、末尾或者中间适当位置添加文字提示或者通用符号提示等标识"，且下载/复制/导出时文件内必须含显式标识。
- 第五条：隐式标识须含"生成合成内容属性信息、服务提供者名称或者编码、内容编号"；鼓励数字水印。
- 第十条：**用户**发布生成合成内容时"应当主动声明并使用服务提供者提供的标识功能进行标识"；任何组织和个人不得恶意删除、篡改、伪造、隐匿标识。
（[中央网信办原文](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)）

**可检测信号 / 工程动作**：
- 产物落盘时必须写元数据：`generator`、`model_id`、`prompt_hash`、`content_id`、`provider_code`。
- 发布链路必须调用平台的 AI 声明开关：番茄有"是否使用 AI"勾选，知乎有「发布设置 → 创作声明 → 包含 AI 辅助创作」。
- **不要做"去水印"**——第十条明确禁止隐匿标识，这是法律风险不是技术风险。

### D5 版权与署名

**现象。** 三个具体问题：
1. **训练数据权属**：模型输出与训练语料的实质性相似风险。
2. **人类作者性**：纯 AI 生成内容在中国的著作权认定存在不确定性（"独创性"要件）。
3. **署名与责任**：批量生产时谁署名、谁担责。

**工程动作**【判断】：
- 保留**人类创作贡献的可举证链路**：大纲人工调整记录、参数选择记录、后处理规则版本、人工终审记录。这不只是法律需要，也是 D3 里"自证不是 AI 粗制滥造"的材料。
- 每本书绑定一个"责任作者"ID，不要匿名批量发布。
- 建立**输入污染检查**：prompt 里不要塞入整段他人作品（few-shot 风格锚必须用授权样本或自写样本）。

### D6 读者信任与"自证困境"

**现象。** 读者对 AI 味极度敏感，"看两段就划走"；同时**误伤**大量发生——手写作者因为用了两个破折号就被评论区追问"这是 AI 写的吧"。

【文献】36氪《消除"罪证"》记录了多起误伤案例：网民用两个破折号被质疑；有人手敲一下午的文案被平台算法误判为未标注 AI 内容而禁言一天；有编剧手写剧本被当成 AI；甚至有学者引用的作者原话被判定为 AI（[36kr](https://www.36kr.com/p/3824601267196037)）。同文还提到维基百科的立场：**不要只依赖 AI 检测工具**，它们错误率不低，且对改写、标记、空格改动敏感。

**工程含义**【判断】：
- **不要追求"通过检测器"，要追求"通过读者"**。检测器是代理指标，读者留存才是目标函数。
- 门禁指标要**双向**设计：既抓 AI 味（假阴性），也抓"过度规整导致的误判"（假阳性）——比如句长 CV 超过 1.6、短句占比超过 0.65 时，可能已经"人工痕迹过重"了。
- 保留创作过程记录（文档历史、大纲手稿、灵感笔记），这是唯一有效的自证材料。

## 6. 为什么 3000 本规模会把这些毛病放大

单本的问题在批量下不是线性叠加，是**相乘**。

### 6.1 模式坍缩：3000 本会互相"抄"

**机制。** 同一套 prompt 采样 3000 次，每次都在分布的高密度区域取样。单本看每一本都"合格"，横向看它们**互相可替代**。

【文献】Shumailov 等人的 Model Collapse 结论是：模型生成内容进入训练会导致**原始分布的尾部消失**，且不可逆（[arXiv:2305.17493](https://arxiv.org/abs/2305.17493)）。我们的场景不是训练坍缩，但**采样层的尾部侵蚀是同一个数学现象**：tail 在采样分布里本来就概率低，3000 次采样里出现次数趋近于 0。

**量化。** `diversity.py` 的 `combined` 是四项相似度的加权和（0.45·4-gram MinHash + 0.30·意象 Jaccard + 0.15·结构序列 + 0.10·开头指纹）。若四项都约为 s，则 `combined ≈ s`；所以**平均 `combined = 0.35` 大致等价于"四项特征的平均重合度都在 35% 左右"**——即每两本书的 4-gram 集合、意象词集合、结构骨架都有约三分之一的交集。这在平台侧就是"同质化严重"，在读者侧就是"我好像看过这本"。

**放大倍数估算**【判断】：单本时，撞梗的期望对数是 0（没有对照）。3000 本时，两两对数 = C(3000,2) = **4,498,500 对**。即使只有 0.1% 的对超过 0.5 相似度，也有 **4498 对** 是明显的重复。这就是"批量"的定义性风险。

### 6.2 评测不可行：人读不过来

**算术。** 3000 本 × 5000 字 = **1500 万字**。

- 按 500 字/分钟的阅读速度：1500 万 / 500 = 30,000 分钟 = **500 小时**。
- 折算成 8 小时工作日：**62.5 个工作日**——而且这只是"读一遍"，不含写评注、比对、返工。
- 如果每本要写 200 字评语 + 比对前文：单本 20 分钟，3000 本 = **1000 小时 = 125 个工作日**。

**结论：人工全检在数学上不成立。** 必须转成"机器门禁 + 人工抽检"。

**抽检的统计学**（Wilson 区间）：抽 n 本，观测通过率 p̂，95% 置信区间半宽为

```
h = z·√( p̂(1−p̂)/n + z²/(4n²) ) / ( 1 + z²/n ),  z = 1.96
```

抽 150 本、p̂ = 0.85 时 h ≈ **±5.7 个百分点**。也就是说抽 150 本只能告诉你"通过率在 79%–91% 之间"——**这个精度不足以支撑"3000 本可发布"的决策**。

要 h ≤ 2 个百分点（p̂=0.85），需要 n ≈ **1225 本**，即 41% 的全检率。这又回到了人力问题。

**唯一出路**：把"合格"从"人判断"改成"代码判定"，人只处理代码判"可疑"的那 5%–10%。这就是第 7、8 节的全部意义。

### 6.3 错误累积：复利效应

**机制。** 单章的错误率 p，在 n 章内不传播时，全书无错概率 = (1−p)^n。但一致性错误是**传播**的（第 3 章写错的人名，第 4–10 章会继续用错），所以实际是超几何衰减。

**量化。**
- 单本 10 个场景，每场景 3% 概率引入一个一致性错误 → 单本"零严重错误"概率 ≈ 0.97^10 ≈ **73.7%**。
- 3000 本 → 期望 **789 本**带严重错误。
- 反过来算：若要求全库 95% 概率无严重错误，需要单本错误率 p 满足 (1−p)^3000 ≥ 0.95 → p ≤ 1 − 0.95^(1/3000) ≈ **0.0017%**。

**单本合格率必须做到 99.998%，才能保证 3000 本里 95% 概率没有一本带严重错误。** 这是不可能靠"提高生成质量"达到的，只能靠**生成即检 + 检不过即重跑**。

**工程结论**：门禁不是"质检环节"，是**生产环节**。它必须在循环里，不能是循环后的一道关卡。

|---|---|---|---|
| 一次性长生成 + 模型自检 | 2 | 6,000 | 自检有讨好倾向，不可信 |
| 分级扩写 + 模型评审 + 模型重写 | 8–15 | 24,000–45,000 | `01-frameworks.md` 4.1 节估算 novel-studio 类方案 30–60 次 |
| **分级扩写 + 确定性后处理 + 确定性门禁** | **3–5** | **9,000–15,000** | 本文推荐 |

**判断**：模型调用次数是成本的主项，确定性代码的边际成本接近 0。**所以 A 层能靠正则修的绝不靠模型修**，C 层能靠状态台账校验的绝不靠模型校验。

## 7. 去 AI 味的可执行手法（23 条）

每条给：**原理 / 落在哪个环节 / 具体做法 / 验收指标**。

环节代号（沿用 `01-frameworks.md` 的 5 步流水线）：

- **① 参数采样** — 决定这本书"长什么样"的组合参数
- **② 大纲** — 三层大纲 + 字数配额 + 伏笔台账
- **③ 正文生成** — 分级扩写（不是一次长生成）
- **④ 确定性后处理** — 纯代码，零模型调用
- **⑤ 确定性门禁** — 纯代码，判过/不过

### 7.1 节奏类（修 A5 / B4）

**手法 1：句长方差注入**
- 原理：直接对抗 burstiness 塌陷。人类句长 CV ≈ 0.95，AI ≈ 0.52【实测】。
- 环节：**④ 后处理**（主）+ ③ 生成约束（辅）
- 做法：对每段做句长序列分析，若 `CV < 0.80`：把最长的 2 句各拆成 2–3 句（在逗号/顿号处拆），并在段内随机位置插入 1–2 个 ≤8 字的独立短句（用"动作+句号"形式，如"他没动。"）。**插入的短句必须从原文的动作/物件里取，不能凭空造。**
- 验收：M1 句长 CV ≥0.85，M2 短句占比 ≥0.28。

**手法 2：短句砸节奏**
- 原理：极短句是"读者换气点"，也是人写文本最强的统计特征。人写 ≤8 字句占 51.9%，AI 占 21.4%【实测】。
- 环节：**③ 正文生成**（prompt 硬约束）
- 做法：prompt 里写死"每 150 字必须出现至少 1 个 8 字以内的独立句子，且该句不得包含情绪词"。生成后用 ④ 校验并补插。
- 验收：`短句数 / 每 150 字 ≥ 1`，全书不达标段落数 =0。

**手法 3：段落长度极化**
- 原理：真实小说的段落长度是双峰的——大量 1–3 行的"重击段"，少量十几行的"展开段"。AI 的段落长度集中在中间带。
- 环节：**④ 后处理**
- 做法：目标分布 `≤15 字: ≥40%`、`≥80 字: ≥8%`。对不达标的文本：把信息密度低的过渡段拆成单句段；把连续的短段合并成一个长段（用分号或直接连接）。
- 验收：M5 段落长度分布双峰检验（`R_short_para ≥0.40` 且 `R_long_para ≥0.08`）。

**手法 4：删掉段末总结句**
- 原理：段末升华是段落级局部最优的产物。段末句的功能应该是"留下一个动作或一个物象"，不是"总结意义"。
- 环节：**④ 后处理**（规则）+ ③（prompt）
- 做法：对每段末句，若命中升华词表（命运/意义/人生/灵魂/永恒/宿命/救赎/人性/尊严/价值/本质/真相/自由/孤独/成长/选择/希望/未来/世界/一切/永远/从此/注定/轮回/羁绊/传承/时代）**且**句长 ≤40 字 **且**不含具体名词 → 删除该句，或替换为段内最后一个具体动作的复述。
- 验收：M9 段末升华率 ≤0.10；末段升华标记 =0。

### 7.2 词汇类（修 A1 / A2 / A7 / A8）

**手法 5：禁用词硬替换表**
- 原理：套话是可枚举的，枚举题就用枚举解。不需要模型。
- 环节：**④ 后处理**
- 做法：`novel-lab/src/ai_flavor.py` 的 `AI_CLICHE` 直接当替换表用。替换策略分三类：
  - **纯删除**（"缓缓地""轻轻地""微微"）→ 删掉，动词自己承担速度感。
  - **动作替换**（"深吸一口气"→ 具体的呼吸动作或直接删；"嘴角勾起"→ 具体的嘴部动作或删）。
  - **上下文白名单**（"一丝"在"一丝不苟"里不替换）。
- 验收：M6 套话密度 ≤3/千字。

**手法 6：逻辑连接词清零**
- 原理：小说靠事件顺序承载因果，不靠"因此/然而/此外"。连接词密度高 = 议论腔。
- 环节：**④ 后处理**
- 做法：`因此/所以/然而/但是/此外/另外/首先/其次/最后/总之/换言之/由此可见/不仅/不但/况且/何况/因而/从而/进而` → 删除或改为分句。保留率上限 20%。
- 验收：连接词密度 ≤4/千字。

**手法 7：成语降频 + 同段去重**
- 原理：成语本身不是问题（人写密度甚至更高【实测】3.40 vs 2.15），问题是**同段连用**。
- 环节：**④ 后处理**
- 做法：维护四字格词典（`ai_flavor.py` 的 `FOUR_CHAR_IDIOM`），逐段扫描；同段 ≥3 个则保留最贴切的一个，其余按白话词典替换（需自建 200 条左右的成语→白话映射）。
- 验收：同段四字格连用 ≥3 的段落数 =0；全书四字格密度 ≤4/千字。

**手法 8：具象词强制配额**
- 原理：具象/抽象比是最强的单指标。人写具象词密度 108.8/千字，AI 49.5/千字【实测】。
- 环节：**③ 正文生成**（主）+ ④ 校验
- 做法：prompt 里写"每个场景必须出现至少 3 个**具体的器物/身体/天气/动作名词**，且这些名词必须与本书已建立的设定一致（不得引入新设定）"。生成后 ④ 用 `CONCRETE_NOUN` 词表校验密度。
- 验收：M7 具象/抽象比 ≥4.0；具象词密度 ≥70/千字。

**手法 9：抽象大词黑名单**
- 原理：抽象词是"空转"的直接信号。
- 环节：**④ 后处理**
- 做法：`命运/宿命/意义/灵魂/存在/永恒/虚空/羁绊/人性/尊严/本质` 出现即人工复核；密度上限 3/千字。
- 验收：M8 抽象词密度 ≤3/千字。

**手法 10：比喻词限额 + 喻体必须来自本书设定**
- 原理：AI 的喻体来自训练语料高频共现（"如同一道闪电"），不是来自场景。
- 环节：**③ 生成**（约束）+ ④（校验）
- 做法：prompt 里禁用 `仿佛/宛如/犹如/好似`，只允许"像……一样"；且**喻体必须是本书世界内存在的东西**（不能在现代都市文里用"如同天外飞仙"）。后处理统计喻体类型/比喻总数。
- 验收：M10 比喻词密度 ≤6/千字；喻体类型/比喻总数 ≥0.5。

### 7.3 情绪与对话（修 A3 / A6）

**手法 11：情绪外化为身体动作**
- 原理：情绪不能"说"，只能"演"。模型没有身体，所以要显式给它身体。
- 环节：**③ 正文生成**（prompt）+ ④（校验）
- 做法：prompt 写死"禁止使用感到/觉得/心中/心里/内心/情绪/心情/心头 + 情绪形容词。情绪只能通过以下四类呈现：身体反应（手指停在半空/喉结动了一下）、动作失误（钥匙插了两次才插进去）、对话内容（答非所问）、物件交互（把烟按进烟灰缸）"。
- 验收：M12 情绪直说密度 ≤4/千字；情绪段落的可观测动作数 ≥1。

**手法 12：信息不对称对话**
- 原理：真实对话的张力来自"我知道的你不知道"。单模型生成对话时所有人共享同一份知识，所以对话没有张力。
- 环节：**③ 对话生成**（关键：对话要单独生成，不要和叙述一起生成）
- 做法：给每个角色维护一份**知识清单**（`knows: [...]`, `does_not_know: [...]`, `wrongly_believes: [...]`）。生成对话时，只把**当前说话人**的知识清单 + 对方的知识清单（用于制造误解）注入 prompt，不注入全知视角。
- 验收：每段对话中"信息不对称"轮数 ≥1（即某角色说的话基于对方不知道的信息，或基于错误认知）；M14 角色声纹 JS 散度 ≥0.30。

**手法 13：对话轮长破坏**
- 原理：人说话是破碎的。AI 的对话每轮都完整。
- 环节：**④ 后处理**
- 做法：随机把 15% 的长台词（>25 字）在语义边界切成两轮，中间插入对方的 2–4 字反应（"嗯。""什么？""你说什么？"）；随机把 10% 的台词截断为未完成句（以"——"结尾），让下一轮由对方接。
- 验收：M13 对话轮长 CV ≥0.70；≤3 字极短轮占比 ≥0.15；未完成轮占比 ≥0.08。

**手法 14：对话占比下限**
- 原理：对话承载性格与信息差，叙述承载氛围。AI 的对话占比显著偏低（5.4% vs 11.9%【实测】，两者都低于网文健康区间）。
- 环节：**② 大纲**（配额）+ ⑤（校验）
- 做法：大纲阶段给每章分配对话字数配额（网文 25%–40%）；不足的章回炉，把部分叙述段改写成对话。
- 验收：M11 对话占比 0.25–0.45。

**手法 15：角色声纹卡**
- 原理：声纹分化是"多人感"的唯一来源。单模型默认把所有角色拉向均值。
- 环节：**② 大纲**（建卡）+ ③（注入）
- 做法：每个角色一张卡，写死：① 3 个专属口头禅/语气词；② 句长偏好（"老周：≤6 字短句，不用形容词"）；③ 禁用词（"老周不说书面语"）；④ 一个语言习惯（"回答问题前先重复对方的话"）。生成时注入，门禁算 JS 散度。
- 验收：M14 任意两角色 JS 散度 ≥0.30；每角色专属词 ≥3 个。

### 7.4 结构与叙事（修 B1–B7）

**手法 16：结构模板反套路抽样**
- 原理：所有书用同一个"起承转合"= D1 坍缩的根源。
- 环节：**① 参数采样**
- 做法：预置 12 种 beat 模板（如"全对话章""全回忆章""这一章什么都不发生""倒叙开场""多线并置"），按书随机抽样，且**强制约束：同一批 3000 本里，每种模板使用率 ≤15%**。
- 验收：M16 结构功能串集中度 ≤0.15；最常见功能串占比 ≤0.35。

**手法 17：代价注入**
- 原理：无代价 = 讨好倾向的叙事投影。
- 环节：**② 大纲**
- 做法：大纲阶段强制写一个"不可逆损失"事件（人死/物毁/关系断裂/能力永久丧失），且**在结局不允许补偿**。生成后 ⑤ 校验"损失事件后是否有对应补偿"。
- 验收：M17 不可逆损失事件数 ≥1；损失/补偿比 ≥2。

**手法 18：伏笔台账闭环**
- 原理：埋而不收是上下文衰减；收了没埋是讨好倾向。两者都靠台账解决。
- 环节：**② 大纲**（登记）+ ⑤（校验）
- 做法：每个伏笔分配 ID + 埋点章 + 回收章；正文生成时用 ID 锚定具体表述；门禁用实体匹配校验"已登记伏笔 100% 在回收章出现"和"结尾 20% 内无无源新名词"。
- 验收：M18 伏笔回收率 =1.0；无源揭示数 =0。

**手法 19：时间戳推进**
- 原理：模型没有内部时钟。
- 环节：**② 大纲**（场景时间表）+ ④（校验）
- 做法：大纲阶段给每个场景一个绝对/相对时间戳；正文必须含至少 1 个可解析的时间标记；后处理校验时间标记单调递增。
- 验收：M19 场景时间标记密度 ≥1/场景；时间倒流次数 =0。

**手法 20：场景信息密度配额**
- 原理："空洞水文"的可量化定义就是信息密度低。
- 环节：**② 大纲** + ⑤
- 做法：每个场景必须包含 ≥1 个"状态改变"（人物关系/知识/位置/能力/目标任一项变化）。大纲阶段标注，生成后校验。
- 验收：M20 信息密度 ρ ≥2.0 事件/千字；无状态改变场景数 =0。

### 7.5 生成参数与库级（修 D1 / D2 / D3）

**手法 21：采样参数按书随机化**
- 原理：同一组 (temperature, top_p, seed) 采 3000 次，结果会聚在同一区域。参数本身必须成为多样性维度。
- 环节：**① 参数采样**
- 做法：每本书从预设的参数网格里抽一组：`temperature ∈ [0.75, 1.05]`、`top_p ∈ [0.88, 0.97]`、`min_p ∈ [0.02, 0.08]`、不同 seed。**禁用贪心解码和 temperature <0.6**（那会直接退化成 A 层全部症状）。
- 验收：库内参数组合的重复率 ≤10%；参数与文本特征（句长 CV、TTR）的相关性检验（应显著相关，否则说明参数没起作用）。

**手法 22：跨书 n-gram 去重拦截**
- 原理：对内撞车的风险远大于对外。
- 环节：**⑤ 门禁**
- 做法：新书入库前，与已入库全部书做 4-gram MinHash 比对（`diversity.py` 的 `pair_similarity`），`combined > 0.35` 直接打回重采样；`0.25–0.35` 进入人工复核队列。
- 验收：M15 库内平均两两相似度 <0.20；超阈值对数 =0。

**手法 23：风格锚点轮换**
- 原理：few-shot 风格锚是"统一声音"的最有效手段，但同一个锚用 3000 次就是最大的坍缩源。
- 环节：**② 之前**（prompt 构造）
- 做法：准备 ≥30 篇真人写样本（各 800–1500 字，风格各异），每本书抽 1 篇作为风格锚，且**强制约束：同一锚文本使用次数 ≤100**（3000/30）。锚文本必须授权可商用。
- 验收：锚文本使用分布的最大占比 ≤3.4%；不同锚产出的文本在句长 CV / TTR 上有显著差异。

> 手法数：23 条（要求 ≥15）。

## 8. 可自动化的检测指标表

**全部指标均为纯代码可算，零模型调用。** 符号：`N` = 汉字总数，`L` = 句长序列（句内汉字数），`P` = 段长序列，`n` = 千字数 = N/1000。

| # | 指标 | 计算方式 | 健康阈值 | 对应毛病 |
|---|---|---|---|---|
| **M1** | 句长变异系数 `CV_sent` | `σ(L)/μ(L)` | **≥0.85**（<0.55 报警） | A5 节奏平权 |
| **M2** | 短句占比 `R_short` | `\|{l∈L : l≤8}\| / \|L\|` | **0.28–0.45**（<0.12 报警） | A5 节奏平权 |
| **M3** | 相邻句长落差 `J` | `mean(\|L[i+1]−L[i]\|)` | **≥9**（<6 报警） | A5 节奏平权 |
| **M4** | 段长变异系数 `CV_para` | `σ(P)/μ(P)` | **≥0.75** | B4 节奏平权 |
| **M5** | 段落极化度 | `R_short_para = \|{p≤15}\|/\|P\|`；`R_long_para = \|{p≥80}\|/\|P\|` | **前者 ≥0.40，后者 ≥0.08** | B4 节奏平权 |
| **M6** | 套话密度 `D_cliché` | `Σ count(w) / n`，w ∈ `AI_CLICHE` 词表（100+ 条） | **≤3 /千字** | A2 万能副词 |
| **M7** | 具象/抽象比 `R_ca` | `(D_con + 0.5) / (D_abs + 0.5)`，D 为词表命中密度 | **≥4.0**（<1.5 报警） | A8 抽象空转 |
| **M8** | 抽象大词密度 `D_abs` | 抽象名词表命中数 / n | **≤3 /千字** | A8 抽象空转 |
| **M9** | 段末升华率 `R_sub` | `\|{段末句含升华词且 ≤40 字}\| / \|P\|` | **≤0.10** | A4 段末升华 |
| **M10** | 比喻词密度 `D_sim` + 喻体多样性 | `Σ count(像/如同/仿佛/宛如/犹如/好似) / n`；`喻体类型数/比喻总数` | **D_sim ≤6/千字；多样性 ≥0.5** | A7 万能比喻 |
| **M11** | 对话占比 `R_dlg` | `引号内汉字数 / N` | **0.25–0.45** | A6 对话失真 |
| **M12** | 情绪直说密度 `D_tell` | `Σ count(感到/觉得/心中/心里/内心/情绪/心情/心头 + 情绪形容词) / n` | **≤4 /千字** | A3 情绪直说 |
| **M13** | 对话轮长 CV | 对引号内每轮算汉字数得 `T`，`σ(T)/μ(T)`；另算 `\|{t≤3}\|/\|T\|` | **CV ≥0.70；极短轮 ≥0.15** | A6 对话失真 |
| **M14** | 角色声纹 JS 散度 | 每角色台词取字 2-gram 分布，两两算 `JSD(P‖Q)`（自然对数底） | **≥0.30 nat**（需按题材标定） | C1 OOC / A6 |
| **M15** | 库内平均两两相似度 | `diversity.py` 的 `combined = 0.45·minhash + 0.30·imagery + 0.15·structure + 0.10·opening` | **目标 <0.20；硬红线 >0.35 即拦截** | D1 模式坍缩 |
| **M16** | 结构功能串集中度 | 按 1/8 切章、功能词典打标得 8 位串；`最常见串占比` | **≤0.15** | B1 模板化 |
| **M17** | 伏笔回收率 `R_fb` | `已回收伏笔数 / 已登记伏笔数` | **=1.0**（5000 字短篇无例外） | B5 伏笔失控 |
| **M18** | 状态冲突率 `R_conf` | 正文三元组与状态圣经比对，`冲突数 / 总断言数` | **<0.02** | C2/C4/C5 一致性 |
| **M19** | 信息密度 `ρ` | `状态改变事件数 / n` | **≥2.0 事件/千字** | D3 空洞水文 / B4 |
| **M20** | 4-gram 重复率 | `Σ_{v>1}(v−1) / n_grams`，n_grams = N−3 | **≤0.002** | A5 / D2 抄袭 |
| **M21** | 句首二字去重率 | `\|set(句首2字)\| / 句数`（要求句数 ≥200） | **≥0.90** | A2 / A5 |
| **M22** | "的"字密度 | `count("的") / (N/100)` | **≤4.0 /百字** | A2 定语堆叠 |

**指标数：22 个（要求 ≥12）。**

### 8.1 综合评分与判级

沿用 `ai_flavor.py` 的加权方案（权重可按题材调）：

```
sub_i = clip( (value_i − human_ref_i) / (ai_ref_i − human_ref_i), 0, 1 )   # 方向由 ai_ref/human_ref 大小自动决定
score = Σ(sub_i × w_i) / Σ w_i × 100
```

| 分数 | 等级 | 动作 |
|---|---|---|
| <25 | A 人味充足 | 直接入库 |
| 25–40 | B 轻度 AI 味 | 入库，抽样复核 |
| 40–55 | C 明显 AI 味 | 打回 ④ 后处理，重跑 |
| 55–70 | D 严重 AI 味 | 打回 ③ 重新生成 |
| ≥70 | F 纯机器感 | 丢弃，重采样参数 |

### 8.2 门禁的判定逻辑（关键：不是打分，是硬规则）

打分用于排序，**门禁必须是布尔判定**，否则无法自动重跑：

```
PASS 当且仅当：
  M1 ≥0.85  ∧  M2 ≥0.28  ∧  M6 ≤3  ∧  M9 ≤0.10  ∧  M12 ≤4
  ∧ M11 ∈[0.25,0.45]  ∧  M13 ≥0.70  ∧  M14 ≥0.30
  ∧ M17 =1.0  ∧  M18 <0.02  ∧  M19 ≥2.0  ∧  M20 ≤0.002
  ∧ M22 ≤4.0  ∧  字数 ∈ [4500, 5500]  ∧  平台格式检查通过
  ∧ M15（与库内比对）<0.35
```

不满足任一条 → 回到指定环节重跑（映射关系写在门禁配置里，如 `M9` 失败 → ④；`M17` 失败 → ③；`M19` 失败 → ③；`M15` 失败 → ①）。
