# 存储与上下文：Agent 到底"记住"什么

> 配套大屏：`out/dashboard.html`（可拖动时间轴，看任意章节的注入内容）

---

## 0. 一句话回答：不是 RAG

这是最容易被误解的一点。

| | RAG（向量检索） | 本架构（时序正典台账） |
|---|---|---|
| 本质 | **找相似的** | **查当时是什么** |
| 存储 | 前文切片 + embedding | 结构化事实 + 有效期区间 |
| 查询 | 相似度 top-k（模糊） | `state_at(entity, N)`（确定） |
| 写第 3000 章问"右臂怎么样" | 可能召回第 2000 章的旧状态 | **必定返回第 3000 章有效的值** |
| 5000 章后 | 百万切片，召回质量持续下降 | 查询成本不变（只查在场实体） |
| 校验 | 无法自动校验对错 | 冲突在写入时报错 |

**写小说需要的不是"相似片段"，是"确切的事实状态"。** 主角现在什么境界、右手好了没有、跟谁是盟友——这些必须精确，不能靠相似度。

一句话：**RAG 是「找相似的」，本架构是「查当时是什么」。**

## 1. 七个存储层

| # | 层 | 文件 | 存什么 | 大小 |
|---|---|---|---|---|
| 1 | **世界观** | `world.json` | 四界 / 36 大境界 / 108 小阶 / 灵根 / 法宝 / 丹药 / 天劫 / 硬规则 | 固定 |
| 2 | **大纲树** | `outline.json` | 总纲 → 卷纲 → 弧纲 → 章纲（4 层） | 随进度增长 |
| 3 | **人物实体** | `canon.json` | 姓名 / 别名 / 声纹（语气·口头禅·绝不说） | 固定 |
| 4 | **时序事实** | `canon.json` | 带有效期的事实：境界、伤势、所在、关系、身份 | 线性增长 |
| 5 | **数值曲线** | `canon.json` | 战力随章节的插值曲线 | 固定 |
| 6 | **伏笔账本** | `canon.json` | 埋设章 / 回收窗口 / 权重 | 线性增长 |
| 7 | **时间线** | `canon.json` | 故事内时间（不是章号） | 线性增长 |
| + | 章节正文 | `chapters/NNNNN.txt` | 每章 4000 字，落盘可断点续跑 | 2000 万字 |

### 关键：**存储总量线性增长，但每章注入量恒定**

- 正典总事实数会从 30 条涨到上万条
- 但每章只注入「在场 2~5 个实体」的当前状态
- 实测：第 1 章 1797 字符，第 5000 章 1969 字符，**漂移 9.6%**

这是 2000 万字可行的唯一原因。

---

## 2. 核心：带有效期的事实

这是整个架构的地基。普通做法是维护一份设定表，写着"林昭，六品，右臂受过伤"。

**这份表在 5000 章后会骗人**——第 3000 章需要知道的是"右臂**现在**好了没有"。

正解：

```python
Fact("c1", "右臂", "断，接不上了",      valid_from=2100, valid_to=2400)
Fact("c1", "右臂", "已愈，但阴雨天会疼", valid_from=2401, valid_to=None)
```

于是：

```
state_at("c1", 2200)  →  {"右臂": "断，接不上了"}
state_at("c1", 3000)  →  {"右臂": "已愈，但阴雨天会疼"}
```

**任意章节都能精确还原当时的状态。**

大屏的甘特图就是把这个画出来了——每条事实是一根横条，从 `valid_from` 到 `valid_to`，白线是当前章。

## 3. 每章注入什么（恒定 ~1900 字符）

`ContextBuilder.build(chapter)` 组装：

| 块 | 约字符 | 作用 |
|---|---|---|
| 作品定位 | 60 | 书名、一句话、进度 |
| **力量体系** | 250 | 当前界 + 当前境界 + 下一阶 + 硬规则 |
| **世界状态** | 520 | 在场实体的当前状态、数值、声纹 |
| 卷/弧目标 | 180 | 这一段要干什么 |
| 本章大纲 | 220 | 这一章写什么 |
| 上章结尾原文 | 200 | 保证文气连贯（摘要做不到） |
| 写作契约 | 600 | 禁用词等硬约束 |

### 三个设计要点

**① 力量体系只渲染"当前 + 下一阶"**，不列 108 阶。
→ 大小恒定，不管第几章都是 250 字符。

**② 世界状态只渲染在场实体**（2~5 人），不渲染全书所有人物。
→ 5000 章后有 30 个人物，但只注入当前在场的几个。

**③ 伏笔只给"未来 20 章内到期的"**，最多 8 条。
→ 不给"所有未回收伏笔"。5000 章会有几十条，全塞进来必然爆窗。

> **这个坑是真踩出来的。** 初版把"所有未回收伏笔 + 所有实体"都塞进去，
> 结果第 1 章 1408 字符、第 5000 章 2799 字符，**翻了一倍**。
> 是 `verify_longform.py` 的 INV-1 抓出来的。

## 4. 写完之后回写什么

每章生成后，`run_chapter()` 会：

1. **正文落盘** → `chapters/00500.txt`（断点续跑依据）
2. **更新人物出场** → `entity.last_appear = 500`
3. **回写新事实** → 若本章有状态变化（受伤、突破、关系变化）
4. **冲突检测** → 新事实写入前与旧事实对撞，不可变事实被改写立即报错

冲突检测实测：

```
❌ 不可变事实被改写：c2.右手 原为「缺了半截小指」(第1章)，现改为「完好无损」
❌ 同章矛盾：c2.右手 同时是「缺了半截小指」和「完好无损」
```

**不依赖事后人工 review。** 5000 章不可能人肉检查。

## 5. 卷末审计：唯一的全局纠偏点

每 50 章（一卷）体检一次，查四件事：

| 检查 | 阈值 | 不通过的后果 |
|---|---|---|
| 数值膨胀 | > 200000 倍 | 读者算不过来 |
| 伏笔欠债 | 逾期 > 3 条 / 累计 > 30 条 | 读者认为作者忘了 |
| 人物遗忘 | 主要人物 > 4 卷未出现 | 读者忘了他 |
| 时间线停滞 | 卷间故事时间未推进 | 时间线混乱 |

> **阈值必须按题材标定。** 初版我把"战力失控"设成 5000 倍，
> 结果把正常数据判成崩了。参考《斗破苍穹》（斗之气 → 斗帝约 1e4~1e6 倍），
> 改成 200000 倍才合理。

## 6. 大屏怎么看

打开 `out/dashboard.html`（或 artifact 地址），七个区块：

| 区块 | 看什么 |
|---|---|
| **① 力量曲线** | 青色线=绝对战力（单调递增），黄色虚线=界内 rank（每界重置成锯齿） |
| **② 三级大纲** | 当前章落在哪个卷/弧/章，四层如何嵌套 |
| **③ 存储层** | 7 个存储层，悬停看"为什么存这个" |
| **④ 事实甘特** | 每条事实的有效期区间，白线是当前章位置 |
| **⑤ 伏笔账本** | 状态随章号变化：未埋 → 已埋 → 应回收 → 逾期 |
| **⑥ 注入内容** | 第 N 章实际发给模型的完整上下文 |
| **⑦ RAG 对比** | 为什么不是 RAG |

**拖动顶部时间轴**，全部七个区块联动更新。快捷按钮跳转到关键节点（入灵界 / 断臂 / 飞升仙界 / 入神界 / 终局）。

### 几个值得看的对比

拖到 **第 2100 章** vs **第 2500 章**：
- ④ 甘特图上"林昭.右臂"的状态条变了颜色
- ⑥ 注入内容里"右臂"从「断，接不上了」变成「已愈，但阴雨天会疼」

拖到 **第 3001 章**：
- ① 曲线跨过界壁，绝对战力继续涨，但 rank 掉回 0
- ⑥ 力量体系变成「仙界 · 散仙初期」

拖到 **第 5000 章**：
- ⑥ 注入块大小依然是 ~1900 字符，和第 1 章几乎一样

## 7. 重建大屏

```bash
python src/build_dashboard.py
```

它会：
1. 调 `export_dashboard.py` 生成 `out/dashboard_data.json`
2. 把数据注入 `out/dashboard_template.html`
3. 输出 `out/dashboard.html`

**要改数据**：编辑 `export_dashboard.py` 里的 `build_canon()`（人物、事实、伏笔）。
**要改样式**：编辑 `out/dashboard_template.html`。
